# 손 GUI: 개별 모터 · 카메라 · 캘리브레이션

휴머노이드 Linux PC의 로컬 데스크톱에서 실행한다. ROS 없이 기존 SocketCAN을
사용하며 팔 관절 CAN 명령은 보내지 않는다. 손은 한 번에 한쪽을 선택한다.
같은 손을 제어하는 기존 SDK/테스트는 먼저 종료한다. 팔이 SDK에 의존해 버티는
상태라면 팔을 받친 뒤 해당 프로그램을 종료한다.

## 설치와 시작

```bash
cd ~/project_humanoid/dexhand_control
sudo apt install python3-tk python3-venv
bash setup_hand_test.sh --gui --camera
bash gui_hand.sh --dry-run
```

처음에는 모의 실행으로 화면을 확인한다. 실제 CAN 테스트는:

```bash
bash gui_hand.sh --hand right --channel can0
```

`can0`는 이미 1Mbps로 활성화되어 있어야 한다. GUI가 팔 CAN 인터페이스를
재설정하지 않는다. SSH 터미널만으로 창이 나타나지는 않으므로 PC의 로컬 화면을
사용한다. 별도 Linux 디스플레이 전달 환경은 사용자 환경에 맞게 설정해야 한다.
Windows에서는 같은 Python 환경에서 `python -m bhl_hand_sdk.gui --dry-run`으로
GUI를 확인할 수 있지만 현재 실제 CAN 전송 경로는 Linux SocketCAN이다.

## 연결과 출력

1. `left`(왼손) / `right`(오른손), CAN 인터페이스, 모의 실행 여부를 선택한다.
2. **CAN 연결 확인**은 PONG·프로토콜 3·보정 해시만 검사한다. 모터를 시작하지 않는다.
3. 처음 전원을 켠 빈손은 **처음 켠 빈손을 펼침으로 시작**을 선택하고 **출력 시작**을 누른다.
   실제 위치를 알 수 없으므로 첫 PWM은 펼침 값으로 직접 적용된다.
4. 이미 PWM이 출력되는 손은 ESP32가 기억한 마지막 PWM을 읽어 이어받는다.
   체크박스를 켰더라도 이어받는 순간 강제로 펼치지 않는다.
5. **유지 HOLD / Esc**는 마지막 PWM을 유지하고 새 목표를 차단한다.
   **PWM 끄기**는 유지력을 잃을 수 있으므로 손이 물체를 잡고 있을 때 주의한다.

모드 변경·창 종료·GUI 이벤트 루프 응답 만료 시 HOLD를 요청한다. HOLD 응답이
없으면 실제 유지 성공을 보장하지 못하며 오류로 표시한다. GUI가 강제 종료되면
ESP32의 기존 watchdog이 마지막 PWM을 유지한다. 기계식 브레이크는 아니다.

## 개별 모터

15개 모터를 한국어 손가락·위치, GPIO와 함께 표시한다. 슬라이더의 0은 해당
모터의 풀림, 100%는 당김이며 PWM 수치의 증가 방향과는 별개다. 슬라이더를
움직이면 해당 모터 목표만 바뀐다. 15개 전체 목표를 기존 프로토콜의 5개 CAN
프레임으로 보내므로 다른 모터 목표는 보존한다. 속도는 초당 전체 범위의 25%다.
엄지 양쪽 당김 비율의 합이 1을 넘으면 거부하고 HOLD한다.

화면의 **목표 µs**와 **마지막 적용 µs**는 다를 수 있다. 후자는 ESP32의 적용
응답/명령 스냅샷 기준이며 실제 손가락 위치는 아니다. 모의 실행은 실물 응답이
아닌 모의 결과라고 표시한다.

## 카메라

카메라 모드에서 번호(보통 `0`) 또는 `/dev/video2` 같은 경로를 입력하고
**미리보기 시작**을 누른다. GUI 안에 미러 영상과 손 랜드마크가 나타난다.
편 손 하나가 보일 때 **출력 시작**을 누른다.

OpenCV가 USB 영상을 읽고 MediaPipe Hand Landmarker가 손의 21개 점을 추정한다.
현재 모드는 손 전체의 펴짐/주먹을 구분하여 최대 25% 당김의 `power` 자세를
보내는 데모다. 개별 손가락 관절 각도의 일대일 추종은 구현하지 않았다.
인식 손이 없거나 둘 이상이거나 입력이 350ms보다 오래되면 HOLD하고,
재인식만으로 자동 재시작하지 않는다. 다시 편 손을 보여주고 시작을 눌러야 한다.
영상 추론은 별도 프로세스, CAN은 별도 스레드, GUI는 주 스레드에서 실행한다.

## 캘리브레이션

1. 캘리브레이션 탭으로 바꾸면 HOLD한다. 출력을 다시 시작한다.
2. 표에서 손가락·위치를 선택한다. PWM을 입력하고 **선택 모터로 전송**하거나
   `±5`, `±25`로 조금씩 이동한다. 다른 모터 목표는 바꾸지 않는다.
3. 끝점을 확인한 뒤 **이 값을 풀림으로 기록 / 당김으로 기록**을 누른다.
   JSON 기록만 바뀌며 즉시 CAN 범위나 펌웨어 설정이 바뀌지는 않는다.
4. **JSON 저장 / 불러오기**로 별도 초안을 보관하고 이어서 편집한다. GPIO·손·모터 순서가
   다른 초안은 불러오기를 거부한다. **펌웨어 + PC 설정 내보내기**는 새 폴더에
   양손 프로필·완전한 업로드 폴더 두 개·일치하는 `dexhand.yaml`과 적용 안내를 생성한다.
5. 바꾼 손의 펌웨어를 업로드하고 프로필 JSON과 SDK YAML을 함께 배포한 뒤
   GUI를 다시 실행한다. 새 폴더의 README 절차를 따른다.

**실시간 이동은 현재 업로드한 펌웨어의 보정 범위 안에서만 가능하다.**
그 밖의 값도 500~2500µs 범위에서 새 초안 끝점으로 기록할 수 있지만 현재
펌웨어로 시험한 값은 아니다. 새 보정으로 펌웨어를 올린 뒤 작은 증분으로
다시 확인해야 한다. 새 범위나 역전 방향의 기계적 안전성은 자동 판정할 수 없다.
풀림과 당김이 같은 값이면 내보내기를 거부한다. 내보내기는 현재 프로젝트를
덮어쓰지 않는다. 값이 달라진 펌웨어와 SDK를 섞으면 profile mismatch로 차단된다.

## 현재 배선 기준

왼손 엄지 끝은 **GPIO18**이다. 오른손 검지 위/아래는 **GPIO32/25**다.
사용자가 예전 표에 적었던 GPIO34/35는 PWM 출력할 수 없다. 양손 CAN은 기존
배선의 **TX=GPIO1 / RX=GPIO3**이며 [GPIO1/3 업로드 안내](CAN_WIRING_GPIO1_3.md)를 따른다.
GUI는 `profiles/left_hand.json`, `right_hand.json`과 SDK 설정이 일치하는지 확인한다.
이 GUI는 PC용이다. ESP32에는 기존 왼손/오른손 프로토콜 3 펌웨어를 사용한다.

## 검증 범위

오프라인 CAN 모사·실제 C++ 수신기와의 통합 검사·GUI 모의 실행을 사용한다.
CAN GPIO1/3 수정본의 전체 자동 검사는 **200개 + 하위 검사 68개 통과**했다.
Windows Tk 실제 위젯 검사와 생성한 빈 영상의 MediaPipe → GUI 영상 전송 검사도 통과했다.
실제 USB 카메라와 사람 손 분류, Linux 화면/CAN 어댑터, 실물 모터 테스트는 별도로
수행해야 한다. 자동 검사 통과가 실물 손의 도달 위치나 유지력을 뜻하지 않는다.

참고: [MediaPipe Hand Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/python),
[Python Tkinter](https://docs.python.org/3/library/tkinter.html).
