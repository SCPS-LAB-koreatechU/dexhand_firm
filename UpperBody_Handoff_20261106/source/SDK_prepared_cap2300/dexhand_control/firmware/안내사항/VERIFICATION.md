# 검증 기록

> 2026-11-04 이후의 현재 코드는 [보완본 안내](CURRENT_SETUP_20261104.md), [프로토콜 3 명세](PROTOCOL_v3.md)를 따릅니다. 이 문서는 이전 버전의 설명 또는 비교·검증 기록입니다.

## 2026-11-03: CAN 상수를 각 스케치 맨 위로 이동

- 각 `.ino` 상단에 `CAN_NODE_ID`, `CAN_CONTROL_ID`, `CAN_POSE_ID`를 지정했습니다. 기본값은 왼손 60/0x03C/0x33C, 오른손 61/0x03D/0x33D입니다.
- `HandController`가 전체 제어/목표 ID를 인자로 받고 해당 값으로 메시지를 구분합니다. 하드웨어 필터도 두 상수에서 공통 비트 마스크를 계산합니다.
- 기본 공식과 다른 ID 0x123/0x456을 지정했을 때 설정한 ID만 처리하고 기존 공식 ID는 무시하는 C++ 검사 **통과**. 기존 제어/조립/타임아웃 검사도 포함됩니다.
- Python unittest **16개**, 생성 파일 일치 검사 **통과**.
- Arduino-ESP32 3.3.12, `esp32:esp32:esp32`에서 왼손·오른손 각각 컴파일 **통과**. 각 스케치 플래시 273,703 bytes, 전역 메모리 22,456 bytes.
- 실제 CAN 수신 필터나 모터를 하드웨어에서 시험하지 않았습니다.

## 2026-11-03: SDK 팔·양손 동시 제어 가이드

- SDK `docs/hand_can_integration.md`에 기존 구현 범위와 추가 구현 대상을 구분하여 기록했습니다. SDK 런타임 코드나 launch를 이번 가이드 작업에서 변경하지 않았습니다.
- Python-CAN 가상 인터페이스의 서로 다른 송신 소켓으로 팔 노드 1~10 목표 500개, 왼손 목표 250개, 오른손 목표 250개를 보내 총 1,000개 목표 프레임의 ID·DLC·순번·그룹을 검사하여 **통과**했습니다. 실제 1초 대기 없이 50회분을 생성한 논리 검사이며 주기 성능 시험은 아닙니다.
- 오른손은 ID 분리 검사를 위해 메모리에서만 왼손 프로필의 노드를 61로 바꿨습니다. 오른손 보정 프로필을 만들거나 검증한 것은 아닙니다.
- 가이드의 Python 예제 구문, 문서 연결 경로, 정상 트래픽의 근사 버스 점유율 산술(22.275%) 검사 **통과**.
- 팔 PDO 응답 500개, heartbeat 50개, 상태 SDO 요청·응답 100개는 부하 계산에 포함했으며 이번 가상 목표 프레임 검사에서 생성한 트래픽에는 포함하지 않았습니다.
- 실제 SocketCAN 인터페이스·USB-CAN·모터를 열거나 구동하지 않았습니다. ROS 노드·공통 정지·실시간 지연의 통합 검증은 해당 기능 구현 이후 필요합니다.

## 아직 확인하지 않은 항목

- 실제 보드 업로드, USB 없는 배터리 부팅, 실물 CAN 왕복/수신 및 모터 동작.
- 현재 통합본의 실물 CAN TX/RX 동작. 예전 도면 GPIO5/34 설정은 이후 기존 배선의 GPIO1/3으로 수정했으며 [GPIO1/3 수정본 안내](CAN_WIRING_GPIO1_3.md)를 따릅니다. 과거 오른손 TIP 펌웨어의 왕복 기록과 현재 통합본의 실물 검증은 별개입니다.
- 실제 PWM 파형·채널 간 위상·최악 응답 지연, 전원 용량·노이즈, 버스 오류 복구의 실물 동작.
- OFF/HOLD/통신 타임아웃과 LEDC 초기화 실패 처리의 실제 모터 동작.
- 손가락 조합별 간섭과 장력, 실제 관절각·접촉·힘.
- 손목 SCS2332와 오른손 프로필.

가상 버스·네이티브 수신기 검사와 컴파일은 하드웨어 검증을 대신하지 않습니다. 기존 팔 SDK와 기존 오른손 TIP 시험 파일은 이 폴더 생성 작업에서 수정하지 않았습니다.
