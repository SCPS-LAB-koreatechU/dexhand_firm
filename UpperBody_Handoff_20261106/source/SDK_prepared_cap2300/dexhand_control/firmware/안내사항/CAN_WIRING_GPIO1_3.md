# GPIO1/3 기존 CAN 배선용 수정본

2026-11-04. **양손 모두 CAN TX=GPIO1(TX0), RX=GPIO3(RX0)**이다.
기존 납땜 배선을 유지한다. 이전 통합 ZIP의 GPIO5/34 설정은 이 배선과 맞지 않았다.
이번 수정본 이름 끝에는 `_can13.zip`이 붙는다.

| 연결 | ESP32 | 트랜시버 |
|---|---|---|
| CAN 송신 | GPIO1 / TX0 | TXD 또는 CTX |
| CAN 수신 | GPIO3 / RX0 | RXD 또는 CRX |

1Mbps, 표준 11비트 프로토콜 3, 왼손 노드 60 / 오른손 61을 사용한다.
15개 모터의 GPIO·풀림/당김 값과 GUI 동작은 유지했다. 프로필 JSON의 CAN 핀이
바뀌어 보정 식별 해시도 바뀌므로 PC 설정과 양손 펌웨어를 함께 배포해야 한다.

## 적용 순서

1. 기존 손 제어 프로그램을 종료하고 모터·보드 전원을 모두 끈다.
2. 업로드할 ESP32의 GPIO1/3과 외부 트랜시버 연결을 분리한다.
   소켓형이면 기존 기판에서 보드를 분리해 업로드한다. 전원이 켜진 채로 탈착하지 않는다.
3. 새 폴더의 `DexHandLeft/DexHandLeft.ino`와 `DexHandRight/DexHandRight.ino`를
   각각 해당 ESP32에 업로드한다. 각 폴더의 `.h` 파일 5개를 함께 유지한다.
   ESP32 Dev Module / Arduino-ESP32 3.3.12, 업로드 속도는 우선 115200을 사용한다.
4. USB와 전원을 분리한 상태에서 기존 GPIO1/3 CAN 배선을 다시 연결한다.
5. PC에도 이 ZIP의 SDK 전체를 배포한다. 기존 `dexhand.yaml` 또는 프로필 JSON을
   덮어씌워 되돌리지 않는다. 기존 ROS 설치본은 다시 빌드해 설치 설정도 갱신한다.
6. 모터 전원을 끈 상태에서 보드·CAN에 정상 전원을 공급하고 먼저 왕복 응답을 확인한다.

```bash
cd ~/project_humanoid/dexhand_control
bash test_hand.sh left ping
bash test_hand.sh right ping
bash gui_hand.sh --hand right
```

PING 성공은 CAN 응답·프로토콜·프로필 일치 확인이며 모터 동작 확인은 아니다.
그다음 모터 전원을 연결하고 GUI에서 한 모터씩 작은 증분으로 시험한다.

## UART0 공유에 관한 제한

GPIO1/3은 보드의 USB-UART 업로드 회로와도 공유된다. 펌웨어는 `Serial.end()`와
로그 비활성화를 유지하지만 USB-UART 칩의 전기적 구동이나 ROM 부팅 메시지를
소프트웨어 설정만으로 제거하지는 못한다. 운전 중에는 ESP32 USB를 분리하고
UART0 시리얼 모니터를 사용하지 않는다. PC의 UCAN USB는 별개다.
보드 회로에 따라 USB를 빼도 공유 회로가 남을 수 있으므로 장기 운전에서는
해당 회로의 분리·전환 가능 여부를 확인해야 한다. 이번 수정으로 그 회로를 검증한 것은 아니다.

이전에 저장된 2026-10-23 오른손 TIP 시험 기록은 GPIO1/3의 실제 CAN 왕복 PASS다.
그 시험은 PWM을 끈 상태였고 확장 ID/문자열 패킷을 쓰는 별도 펌웨어였다.
현재 양손 프로토콜 3의 실물 통신·모터 동작은 재업로드 후 별도로 확인해야 한다.

## 수정본 검사

Arduino-ESP32 3.3.12로 양손 스케치를 컴파일하고, 전체 자동 검사 200개와 하위 검사
68개 및 실제 Tk GUI 모의 실행을 확인한다. GPIO1/3 프로필·생성 스케치·PC 해시의
일치도 검사하며, 이전 ZIP과 비교해 15개 모터의 핀과 보정값이 동일한지 확인한다.
검사 기록과 바이너리 SHA256은 `BUILD_MANIFEST_20261104.json`에 기록한다.
