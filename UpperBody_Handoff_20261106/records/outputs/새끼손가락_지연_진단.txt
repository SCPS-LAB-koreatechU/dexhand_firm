새끼손가락 펼침 지연 진단 · 2026-11-05

확정한 소프트웨어 원인
SDK YAML의 max_speed는 2.0 범위/초였으나 GUI worker가 min(max_speed, 0.25)로 강제 변경했습니다.
따라서 전체 범위 명령에 4초가 걸렸습니다. SDK 설정 그대로면 명령 보간 시간은 0.5초입니다.
오프라인 재현 시험에서 새끼 세 채널을 당김→풀림으로 바꿨을 때 4.00초/0.50초가 재현됐습니다.
이 시간은 PWM 명령 보간 시간이며 실제 손가락 도달 시간은 아닙니다.

적용한 수정
1. GUI의 숨은 0.25 상한 제거. 이제 검증된 SDK max_speed 설정을 그대로 사용합니다.
   현재 설정 2.0 범위/초, 전체 범위 명령 약 0.5초. GUI에 이 시간을 표시합니다.
2. 이미 출력 중인 손의 펼침은 불필요한 ARM/PING을 거치지 않고 목표를 갱신합니다.
   출력 대기·재연결 상태에서는 기존 시작 확인 절차와 프로필 검사를 유지합니다.
3. GUI 기록에 worker 명령 수신 시각, 펼침 목표 설정 시각, 5개 CAN 프레임을
   OS 송신 큐에 넣은 시작/종료 시각과 프레임 수, ACK 해석 시각을 추가했습니다.
4. 보드 PWM/보류/워치독/RX_OVERFLOW/CAN_RECOVERED 플래그, TX/RX 오류 수,
   부팅 ID·업타임, 마지막 확인 PWM과 확인 시각을 기록합니다.
   타임스탬프는 호스트 기준이며 실제 CAN 선로·서보 위치 측정 시각이 아닙니다.
5. 화면에 PWM 명령 변경 중/목표 확인을 구분해 표시합니다.

남은 원인 구분
새끼 특유의 추가 지연을 확정하려면 서보 출력축/풀리와 손가락 반응을 함께 봐야 합니다.
축이 먼저 움직이고 손가락이 늦으면 축 이후 힘줄 유격·마찰·동작 구간을 우선 조사합니다.
축부터 늦으면 PWM 파형·서보 전원·서보 자체 반응을 분리 측정해야 합니다.
현재 CAN 프로토콜에는 실제 위치·전류·서보 공급전압 센서값이 없습니다.
이 관측 없이 새끼 특유의 원인을 통신/기구/서보 중 하나로 확정하지 않습니다.
