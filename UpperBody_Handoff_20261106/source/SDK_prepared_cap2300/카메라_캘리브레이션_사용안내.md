# 오른손 카메라 추종·자세 대응 캘리브레이션 (2026-11-05)

모터의 GPIO와 풀림→당김 PWM 끝값은 사용자가 확정한 값 그대로다. 카메라 캘리는 이 범위 안의 모터 조합과 사람 손 자세를 연결한다. 기존 SDK 실행 경로와 별도로 준비한 버전이다. 왼손 로봇은 이번 구현 대상이 아니다.

## 실행

이 문서가 들어 있는 SDK 디렉터리에서 실행한다.

```bash
cd /home/scps-ubuntu1/Desktop/UpperBody_SDK_0.2.0_20261105_camera_retarget/dexhand_control
bash setup_hand_camera.sh
bash camera_calibration.sh
```

기본은 모의 출력이다. 카메라 없이 화면과 흐름만 확인하려면 `bash camera_calibration.sh --demo`를 쓴다. 합성 랜드마크 데모이며 실제 카메라 시험이 아니다. 실제 카메라 번호/영상 경로와 사용자 손 Right/Left를 선택한 뒤 영상 시작을 누른다.

실물 송신은 `bash camera_calibration.sh --live`로 구분한다. 오른손 CAN 채널은 can1, 1Mbps, 노드61이다. 이 버전은 이전에 준비한 **수신 전용·PWM 별도 태스크 펌웨어**와 함께 쓴다. 실제 보드에 그 펌웨어를 업로드했는지는 확인되지 않았다. PC의 대응표만 추가/수정하는 경우에는 PWM 끝값과 GPIO가 같으면 펌웨어를 다시 업로드할 필요가 없다.

CAN 소켓 접속 → 명시적 전체 펼침 → 수동 슬라이더 순서다. 최초 펼침은 현재 실물 위치를 읽을 수 없으므로 사용자가 명시적으로 실행한다. SENT는 OS 송신 큐에 넣었다는 의미이며 보드 적용·실제 위치 확인이 아니다. 자동 접속/자동 재개하지 않는다.

## 자세 등록 순서

1. 사람과 로봇 손을 모두 편다. 등록 대상 `전체`, 자세 이름 `펴기`로 첫 기준 자세를 기록한다.
2. 검지부터 새끼까지 하나씩 선택한다. 사람 손을 25%, 50%, 75%, 완전히 접은 자세로 유지하고, 수동 탭에서 로봇이 비슷해지도록 맞춘 뒤 각 자세를 등록한다. 위·아래 함께 당기기 슬라이더는 두 모터의 **당김 비율**을 함께 바꾸며 TIP은 별도다. 모터마다 PWM 이동 폭과 방향이 달라도 0~100%의 의미는 같다.
3. 끝마디만 접기, 손가락 좌우 벌림처럼 따로 재현할 자세도 기록한다. 그 구조로 재현하지 못하는 자세까지 그대로 따라간다고 가정하지 않는다.
4. 엄지는 검지·중지·약지·새끼에 각각 향하는 자세를 만들고, 각 방향에서 약/중/강 굽힘을 추가한다. 왼쪽·오른쪽·TIP 세 모터를 조절해 대응시킨다. 방향과 굽힘을 한 개 슬라이더로 고정하지 않는다. 현재 펌웨어의 엄지 좌우 정규화 당김 합≤100% 조건은 유지한다.
5. 각 등록 전에 사람 손을 약 0.5초 이상 고정하고(느린 영상이나 프레임 중단이 있으면 더 오래 유지) 로봇의 실물 자세도 눈으로 확인한다. PC 명령이 목표에 도착한 뒤 실물 확인 체크를 선택해 등록한다. 이 체크는 위치 센서 측정을 대신하지 않는다. 대응표를 JSON으로 저장한다.

손가락별 서로 다른 자세 3개는 추종 시작의 최소 조건일 뿐이다. 넓은 움직임을 다루려면 위의 중간 자세와 실제로 자주 쓰는 조합을 충분히 기록한다. 가까운 등록 자세 최대4개의 모터 조합을 보간하고, 등록 영역에서 멀어지면 HOLD한다. 모의 출력으로 만든 샘플은 실물 추종에 사용하지 않는다. 저장 파일의 손 구분·프로필 태그·PWM 끝값이 현재 SDK와 다르면 불러오지 않는다.

카메라 추종은 수동 출력 준비 후 `카메라 추종 시작`으로 별도 실행한다. 영상 만료, 손 인식 상실/다른 손, 미등록 영역은 HOLD하며 다시 손이 보여도 자동 재개하지 않는다. HOLD는 현재 PWM 유지 요청이다. 전원 차단이나 기계적 정지를 보장하는 버튼이 아니다.

## 도착 시간 맞추기

15개 모터 명령을 같은 진행률로 보간한다. 예를 들어 어떤 모터가 400µs, 다른 모터가 800µs 이동해도 같은 진행률로 목표에 도달하도록 명령한다. 이는 명령의 도착 시간이다. 부하·서보 속도·힘줄 늘어짐 때문에 실제 움직임이 같은 시각에 끝난다는 뜻은 아니다.

실제 시간 보정은 고정한 카메라 영상으로 각 모터의 풀림→당김 이동을 관찰해 걸린 시간을 기록한다. GUI에서 손가락 하나를 선택하고 위/아래/끝 순서(엄지는 왼쪽/TIP/오른쪽)의 전체 범위 시간 3개를 쉼표로 입력한다. 기본 0.5초는 실측값이 아니다. 입력한 시간이 느린 모터에 맞춰 명령 속도를 낮추는 데 쓰인다. 방향·하중에 따른 비선형 지연은 별도 실물 검증이 필요하다.

## 휴머노이드 PC에서 실행

```bash
bash ~/dexhand_control_camera/camera_calibration.sh
```

기본 모의 출력이며 실제 CAN을 열지 않는다. 카메라 없는 합성 데모는 같은 명령 뒤에 `--demo`를 붙인다. 실물 송신은 배선·펌웨어·CAN 상태를 확인한 뒤 `--live`로 명시한다. 기존 GUI와 동시에 실행하지 않는다.

X5의 새 전용 가상환경에서는 MediaPipe1.2.2가 모델 생성 시 AES CPU 기능 오류로 종료되어 0.10.18로 교체했다. `requirements_camera_rdk_x5.txt`에 호환 조합을 고정했고, `setup_hand_camera.sh`는 모델을 실제로 생성해 빈 영상 추론까지 검사한다. import 성공만으로 준비 완료라고 표시하지 않는다. 설치 파일은 [MediaPipe 공식 PyPI 배포](https://pypi.org/project/mediapipe/0.10.18/)를 사용했다.

GUI는 같은 주기에 쌓인 상태 중 최신 값만 그리되 모든 상태를 로그에 보관한다. 자세 등록은 0.45초 이상의 안정 구간과 최소5개 관측을 요구하며, 관측 사이 0.3초 초과 중단 또는 마지막 영상 0.25초 초과 지연은 허용하지 않는다. 부하로 영상이 끊기면 잠시 같은 자세를 더 유지해 다시 등록한다.


## 2026-11-05 현재 카메라 세션

SD카드 통신 오류로 보드 루트가 읽기 전용인 상태에서, 실제 카메라 테스트를 위해 `/run/user/1000/bhl_hand_camera_session`의 RAM에 별도 실행본을 준비했다. 루트 쓰기 재마운트나 파일시스템 복구는 하지 않았다. 전원을 끄면 RAM 실행본은 사라지며, 이 Ubuntu PC의 `outputs/camera_calibration_RAM_session_20261105.tar.gz`에 소스·모델·실행 도구를 보존했다.

실제 ZED2i 카메라의 스테레오 좌우 영상을 한 손으로 중복 인식하지 않도록 이름을 확인해 왼쪽 672×376 영상을 선택한다. 일반 웹캠은 자동으로 자르지 않는다. MediaPipe0.10.18의 XNNPACK 스레드를4개로 설정했다. 보드의 빈 영상 벤치마크는1개227ms→4개67ms, 실제 영상 수신 후 GUI까지 지연은 검수 때 약0.1초였다. 실제 손을 보여준 상태의 인식 정확도는 별도 확인이 필요하다. 영상 신선도/추종 HOLD 기준은 완화하지 않았다.

`BHL_HAND_DATA_DIR` 환경변수로 로그·미리보기·자동 저장을 RAM의 `data` 아래에 둔다. 자세 등록·삭제·시간값 수정 시 `calibration/autosave_correspondence.json`에 저장한다. 모의 샘플은 계속 실물 확인되지 않은 초안으로 남는다. 기본 실행에서는 기존 홈 경로를 사용한다.

`work/camera_session_backup.py`가 이 GUI 세션이 끝날 때까지 RAM 자료를 약2초 주기로 SSH를 통해 현재 Ubuntu PC의 `outputs/hand_camera_session_20261105`로 복사한다. GUI에서 백업 상태를 표시한다. 백업이 연결되지 않은 상태에서 전원을 끄면 마지막 미전송 RAM 자료는 잃을 수 있다. 영상 파일은 자동 녹화하지 않으며 인식 특징·프레임 시각·동작 요청·오류와 대응표를 보존한다.

이 시점에 보드에서 손용 USB CAN `can1`은 보이지 않는다. 현재 GUI는 실제 영상 입력과 모의 CAN 출력이다. 사용자가 실물 손과 PWM 조합을 맞춰 등록하려면 CAN 연결과 올바른 펌웨어를 확인한 뒤 실물 모드로 실행해야 한다. 모터는 자동 활성화하지 않는다.
