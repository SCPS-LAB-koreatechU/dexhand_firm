# 손 CAN 프로토콜 v1

> 2026-11-04 이후의 현재 코드는 [보완본 안내](CURRENT_SETUP_20261104.md), [프로토콜 3 명세](PROTOCOL_v3.md)를 따릅니다. 이 문서는 이전 버전의 설명 또는 비교·검증 기록입니다.

표준 11비트 Classical CAN, 1Mbps, 리틀엔디언입니다. GPIO 번호와 펄스 보정 계산은 CAN 목표 안에 넣지 않습니다. PC가 계산한 실제 PWM 펄스폭 µs를 보냅니다.

## ID

```text
CAN ID = (function << 7) | device_id
```

| 용도 | function | 왼손 60 | 오른손 61 |
|---|---:|---:|---:|
| 제어 | 0 | 0x03C | 0x03D |
| PWM 목표 | 6 | 0x33C | 0x33D |

왼손 프로필은 `profiles/left_hand.json`, 스케치는 `firmware/DexHandLeft`이며 노드 60입니다. 오른손은 `profiles/right_hand.json`, `firmware/DexHandRight`이며 노드 61입니다. 팔 ID 1~10과 중복되지 않습니다. CANopen 전체 구현이나 팔의 float32 PDO 형식과 동일한 데이터 규약은 아닙니다. 손 노드는 손 전용 µs 형식을 해석합니다.

펌웨어의 CAN 설정은 각 `.ino` 상단의 `CAN_NODE_ID`, `CAN_CONTROL_ID`, `CAN_POSE_ID` 상수에 있습니다. 기본값은 위 표와 같으며 값을 바꾸면 PC 송신 측도 같은 설정을 사용해야 합니다.

확장 ID, RTR, 잘못된 ID·DLC는 무시합니다. 노드 0의 브로드캐스트 명령도 해석하지 않습니다. SDK 팔의 하트비트 function 14와 Ping/SDO에는 응답하지 않습니다.

## 목표 프레임

목표 CAN ID에 DLC 8로 보냅니다.

| 바이트 | 의미 |
|---|---|
| 0 | 세트 순번 uint8, 0..255 반복 |
| 1 | 상위 4비트 버전 1, 하위 4비트 그룹 0..4: 0x10..0x14 |
| 2..3 | 그룹의 첫 번째 모터 목표 uint16, µs |
| 4..5 | 두 번째 모터 목표 uint16, µs |
| 6..7 | 세 번째 모터 목표 uint16, µs |

| 그룹 | 모터 번호 |
|---:|---|
| 0 | 1, 2, 3 |
| 1 | 4, 5, 6 |
| 2 | 7, 8, 9 |
| 3 | 10, 11, 12 |
| 4 | 13, 14, 15 |

예: 순번 7, 그룹 0, 1775/700/1750µs는 `07 10 EF 06 BC 02 D6 06`입니다.

PC는 같은 순번의 5개 프레임을 연속으로 보내고 다음 제어 주기에서 순번을 1 증가시킵니다. 권장 주기는 50Hz입니다. 첫 그룹부터 마지막 그룹까지 수신 마감은 기본 20ms입니다. 검증된 모든 값이 모이면 그 즉시 PWM 갱신을 수행합니다. 별도의 적용 프레임은 필요하지 않습니다.

수신기가 허용하는 순번 변화는 `(새 순번 - 이전 순번) mod 256`이 1..127인 경우입니다. 255→0은 정상입니다. 이미 완성한 순번의 반복은 무시합니다. 미완성 세트보다 새로운 순번이 들어오면 이전 미완성 세트를 폐기합니다. 순서가 뒤바뀐 그룹도 같은 세트 안에서 받을 수 있습니다. 서로 다른 값의 중복 그룹, 개별 모터 범위를 벗어난 값, 수신 마감 초과는 해당 순번 전체를 무효화합니다.

PC 프로그램을 새로 시작하면 START 제어 프레임으로 순번 기준을 초기화합니다. 타임아웃·CAN 복구 후에는 순번 기준도 초기화하므로 새 완성 세트를 받으면 자동 재개합니다. 이 순번은 순서 판정용이며 전송 시각이나 실제 모터 위치를 뜻하지 않습니다.

## 제어 프레임

제어 CAN ID에 DLC 2, `[mode, device_id]`로 보냅니다. 기존 SDK의 `RecoilBus.set_mode()`로도 만들 수 있습니다.

| mode | 이름 | 동작 |
|---:|---|---|
| 0x00 | OFF | PWM 중단, 목표 프레임 차단, 순번 초기화 |
| 0x01 | START | PWM 중단, 순번 초기화, 다음 완성 목표 자동 출력 허용 |
| 0x02 | HOLD | 마지막 PWM 유지, 목표 프레임 차단, 순번 초기화 |
| 0x13 | RESUME | 마지막 PWM 유지, 순번 초기화, 다음 완성 목표 적용 허용 |

예: 왼손 START = ID `0x03C`, DLC 2, `01 3C`.

부팅 기본값은 목표 적용 허용입니다. START는 USB 조작이나 필수 ARM 절차가 아니라 새 PC 송신 세션을 위한 CAN 명령입니다. 명시적 OFF/HOLD 이후에는 START 또는 RESUME를 보내야 합니다.

응용 계층 ACK나 상태 응답은 없습니다. CAN 하드웨어 ACK는 버스에 수신 가능한 노드가 있다는 의미이며, 손 펌웨어가 목표를 적용했다는 확인은 아닙니다. 실제 관절 피드백도 제공하지 않습니다.
