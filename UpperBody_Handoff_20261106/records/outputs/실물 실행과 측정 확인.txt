실물 실행과 측정 확인 — 2026-11-02

현재 확인된 상태
- 현재 사용자가 띄운 demo.launch.py는 dry_run:true인 연습 모드다.
- 실물 모드 서버와 demo 컨트롤러를 같은 ROS 도메인/이름으로 동시에 실행하지 않는다.
- 현재 can_left에서는 왼팔 ID1,3,5,9가 응답한다. ID7(왼쪽 팔꿈치)은 초기에는 응답했으나 마지막 점검 및 반복 ping에는 NO_REPLY였다.
- 오른팔 ID2,4,6,8,10도 이 버스에서 응답하지 않는다. 응답 없는 모터의 상태·전류·토크는 추정해 채우지 않는다.
- 이번 작업에서 모터를 켜거나 목표 각도를 보내지 않았다.

1. 서버에서 실물 코드 시작

기존 demo를 실행한 터미널에서 Ctrl+C로 종료한 뒤:

ssh sunrise@172.18.49.21
source ~/humanoid_sdk/env.sh
ros2 launch bhl_bringup robot.launch.py dry_run:=false

시작 시 출력은 꺼져 있다. 보드값·전기적 엔코더 보정 테이블을 읽기만 해서 자동 기록한다. ID7 연결 상태를 먼저 확인하고 팔을 받친 상태에서 작은 각도로 확인한다. 관절·전류·토크·비상정지 보호는 유지했다.

2. RViz와 슬라이더

조작 PC에서 기존 demo/arm_controller를 종료한 뒤:

source ~/humanoid_sdk/env.sh
ros2 launch bhl_bringup remote.launch.py

서버와 PC의 ROS_DOMAIN_ID는 같아야 한다(기본92). remote는 제어기 없이 RViz와 SDK 슬라이더만 띄운다. SDK 슬라이더가 실물 목표를 보낸다. RViz나 joint_state_publisher_gui로 그림만 움직이는 것은 실물 구동 명령이 아니다. 이 작업은 서버 코드에 적용했으므로 PC의 GUI에 새 측정 툴팁을 보려면 PC 패키지도 업데이트해야 한다. 기존 SDK 슬라이더의 목표/서비스 형식은 호환된다.

서버의 env.sh에 로봇 description 설치 경로 자동 탐색을 추가했다. 분리한 연습 모드에서 /robot_description(72677자), /joint_states(32관절), /tf(32변환) 발행을 확인했다.

3. 측정 화면 보기(서버의 별도 SSH 터미널)

source ~/humanoid_sdk/env.sh
ros2 run bhl_arm_sdk arm_log

한 번만 출력:
ros2 run bhl_arm_sdk arm_log --once

최신 세션 상태의 모든 필드를 CSV로 내보내기:
ros2 run bhl_arm_sdk arm_log --csv ~/bhl_logs/arm_latest.csv

특정 기록 선택:
ros2 run bhl_arm_sdk arm_log --file /home/sunrise/bhl_logs/arm_telemetry/arm_20261102T083748.558930Z.jsonl --once

이 뷰어는 파일만 읽는다. 로봇에 명령을 보내지 않는다. 실시간 화면의 UTC 시각, HARDWARE/DRY RUN 표시, 각 값의 조회 경과시간을 확인한다. 종료된 세션의 파일을 선택하면 과거 기록을 보여준다.

4. 자동 저장되는 데이터

서버 디렉터리: /home/sunrise/bhl_logs/arm_telemetry/
파일명: arm_<UTC시각>.jsonl
실물 코드를 새로 실행할 때마다 새 파일을 만든다. 실행 콘솔에도 절대 경로를 표시한다.
파일당100MB, 이전9파일, 세션당약1GB로 회전한다. 이 범위를 넘은 오래된 회전분은 삭제된다. 다른 세션은 자동 삭제하지 않는다. log_dropped/log_error/can_capture_error를 확인한다.

- 매 제어 주기(설정50Hz): 목표/명령/측정 각도, 측정 속도, live, 정지/진행 대기 상태, 제어 시간.
- 10Hz 전체 상태: 개별 보드값과 각각의 조회 경과시간. CSV는 이 전체 상태의 모든 필드를 내보낸다.
- 보드 일반 레지스터68개: firmware/MODE/ERROR, 기어비, Kp/Ki/Kd, 토크/전류/전압/속도/위치 제한, 위치·속도·토크 목표/지령/측정, dq 및3상 전류, dq·3상 전압 지령, 제어 적분값, 필터, 모터 상수·상순서·극쌍수, 엔코더 원시 카운트·회전수·각도·속도·오프셋 등.
- 전기적 엔코더 보정 테이블128개/응답 모터: 시작 시 스냅샷 이벤트에 저장.
- 별도 수신 전용 CAN 소켓: 원본 프레임 ID·데이터·오류 여부·커널 시각. 제어기의 응답을 소비하지 않고 송신하지 않는다.
- 상태 전환 이벤트, 시작 설정 전체, 소스 해시, 커널 정보, 시작 CAN 링크 상태/카운터.

보드 레지스터는 CAN으로 순환 조회한다. 50Hz 제어 루프라 해도 모든 전류·토크·엔코더 항목이50Hz로 동시에 측정되는 것은 아니다. MODE/ERROR가 우선이며 나머지는 빠른 전류·토크·전압 조회80%, 추가54항목 갱신20%로 나눈다. actual board_age_s를 확인한다. 고속 과도현상을 모두 잡는 오실로스코프 대체품은 아니다.

원본 JSONL에는 CSV에 없는 제어 주기 기록, CAN 프레임 및 보정 테이블 이벤트가 있으므로 분석용으로 원본도 보관한다.

5. 값의 의미와 측정할 수 없는 항목

Iq는 모터 dq 상전류로 배터리/BMS/전원공급기 전류가 아니다. 왼팔에서 읽힌 실제 전류 상한은20A였다(22A로 변경하지 않음).
보드 토크는 Kt·전류·보드 기어비로 계산한 추정값이며 출력축 토크 센서값이 아니다. ideal_joint_torque_estimate는 효율·기어 미끄러짐을 반영하지 않는다.
지원 펌웨어에는 실제 온도·감속기 출력축 각도·외부 토크 센서·배터리 전류 측정 레지스터가 없다. 해당 값은 측정했다고 표시하지 않는다.
zero:start에서 enable 전에는 영점이 없으므로 joint_reference_valid:false이며 측정 각도는 뷰어에서 -로 표시한다. 원시 보드/엔코더 각도는 별도 기록된다.

6. 검증과 남은 분석

회귀 테스트48개 통과, 서버 빌드 성공.
서버 설치본의 로그 뷰어 동작 확인.
초기90초 읽기 전용 점검은5모터 응답, 로그 누락0.
확장 측정 점검은 약45초, 응답4모터의68항목과128개 보정 테이블 각각 수집, CAN 원본10010프레임, 제어 주기2115개, 로그 누락/오류0. 모든 모터는IDLE였으며 CAN 캡처에서도 NMT/Flash/PDO2/heartbeat/SDO쓰기 명령이 없음을 확인했다.
ID7은 초기 응답 이후 미응답으로 바뀌었다. 이를 게인 부족으로 단정하지 않는다. 전원·배선·보드 상태 확인이 필요하다.
실제 올라가는 중 떨림과 하중 유지는 아직 실물 구동 검증 전이다. 사용자가 조작하며 증상을 재현하면 이번 로그로 추종 실패, 토크·전류 포화, MODE/ERROR 변화와 통신 중단의 순서를 분석할 수 있다.
